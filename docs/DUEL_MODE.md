# 双人对战 v1 / C31 设计冻结

2026-10-18，用户要求设计双人对战并准备DSH任务。C31设计、C32共享模拟、C33服务与C34房间/驾驶界面现均已完成。本机开发与生产双页面验证通过，独立双人入口为/?mode=duel，双击start-duel.cmd可启动；两个单人任务仍独立。没有公开部署，跨设备/真实网络和真人平衡仍待C35。服务接口见[DUEL_SERVER.md](DUEL_SERVER.md)。

入口：[共享契约](../src/shared/duel-contract.ts)、[DSH任务书](tasks/DSH_DUEL.md)、[可复制提示词](../DSH_DUEL_PROMPT.md)。

## 玩家看到的玩法

主菜单增加“双人对战”。一人创建房间并复制六位房间码，另一人在同一服务地址输入房间码；双方各点准备，3秒倒计时后进入战场。两人驾驶性能完全一致的Eta-2，以红/蓝装饰和玩家编号区分，模型沿用现有资产。

这是共和国训练演习，狩猎者级为静止障碍与掩体，不开炮、不受伤，没有AI编队或任务波次。模式入口与原有两任务分开，联机没有全局暂停；Esc仅打开本地菜单并释放输入，明确提示战斗继续。失焦也只释放输入，不能暂停另一人。打开菜单/失焦时立即提交中性操控帧，保持连接心跳；如果浏览器节流，服务器250ms输入超时规则仍生效。

先得3分获胜。每轮一条命，一方阵亡给另一方1分，撞舰阵亡也算对方得分；双方同一个模拟步阵亡为平局、不加分。未结束整场时等待5秒，双方同时恢复生命、弹药、能量、热量和冷却，清空所有残弹，重置位置后直接开始下一轮；等待阶段最后3秒显示倒计时。采用双方同时重生，避免获胜方残血或停在对手出生点。

累计实际战斗模拟时间最多10分钟，不计准备、倒计时和轮间等待。到时高分方获胜，同分平局；同一步先结算死亡和得分，再判3分胜利，最后判时间上限。整场结算后两人再次准备可原房间重赛。显示比分、阶段倒计时、对手方位/血量、自己的武器/护盾状态和网络往返延迟。

## 联网与开发架构

采用Node.js 24独立服务与WebSocket。浏览器使用原生WebSocket，服务端使用ws；C33已固定ws 8.22.0及相应Node/WS类型依赖并更新锁文件。浏览器不能打包ws。服务端设置maxPayload=8192、关闭permessage-deflate；不引入账号、数据库、匹配大厅、聊天、排行榜、WebRTC或商业联机服务。

服务端是最终裁判：以60Hz推进两架战机、冷却、鱼雷锁定、扫掠碰撞和比分。客户端只能提交归一化操控与按钮，不能提交位置、血量、得分、命中、受害者ID或dt。禁止把目前FlightWorld复制两份后仅同步位置：它的player状态和渲染碰撞资源仍然耦合，需要Codex抽出双玩家模拟。现有单人FlightWorld/RelayWorld继续独立运行。

服务端快照方向已确定：协议版本、房间码、matchId/roundId、serverTick、阶段/比分/剩余时间、每个玩家lastProcessedSeq、位置/四元数/速度/血量/武器与护盾状态、当前弹体和带编号的效果事件。只发游戏公开数据，不发内部connectionId；不要由DSH提前造一套与实际模拟不匹配的快照。

客户端每秒采样60个输入帧、每秒发送30条input消息，每条含1–2个连续采样帧；每个物理帧seq递增。同一连接输入队列最多6帧，溢出时拒绝新消息并发出错误，不能无限积压或用客户端输入加速服务器。服务端每模拟步最多消费一帧；队列空则沿用最近的轴向/boost/fire，但torpedo/shield脉冲归false。超过250ms未收到有效输入，改为全部中性输入；速度按正常飞行逻辑延续，不冻结世界。丢弃已消费seq、旧matchId/roundId，round变化时清空队列和按钮状态。seq一场内持续递增，重赛归零；锁定、冷却、发射结果全由服务器决定。

每秒发送20份快照。本地先预测自己的运动，快照到达后丢弃已确认输入，从权威状态重放未确认帧并平滑修正；对手和弹体用约100ms缓冲插值，最多外推100ms，之后保持最后可用状态并显示网络提示。客户端可预测炮口特效，命中、扣血和比分等待服务器；事件按编号去重。首版不做服务器回溯命中，低延迟局域网优先，跨网延迟由后续实测决定是否需要补偿。

舰体遮挡/碰撞必须与画面一致。Codex负责从现有舰体几何导出共享的紧凑碰撞数据和加速索引，服务端在无WebGL环境加载；客户端预测用同一份数据，不允许服务端将整艘舰替换成大包围盒而画面允许穿过。飞船扫掠体积、障碍命中、盾反弹及边界由两端共享实现。DSH本批不碰三维算法或模型导出。

服务器每次定时唤醒最多追5个模拟步，积压时降低模拟推进速度并记录负载，不扩大dt、不追补无限步。房间所有计时按模拟tick计算，因此过载时10分钟不是严格墙上时钟10分钟。客户端不得通过发消息推进tick。

## 房间、连接与部署

房间码使用DUEL_ROOM_ALPHABET随机生成6位，随机源由服务端crypto提供，碰撞重试最多16次。一个连接最多属于一个房间，一间最多两人；连接ID由服务端生成，不能由客户端自报。首版默认最多16房间、32个已升级连接，同步握手/预订名额，超限明确拒绝；空房间立即移除。只有一人且未开局的房间120秒无有效活动删除；已结算房间120秒无重赛或成员变化删除，发送closed再关闭连接；这些墙上时钟资源清理由服务层处理，不放进DSH纯房间状态。

不做断线续局：主动离开或已确认断开，正在对战/轮间等待时判另一方获胜，显示“对手离开”而非击毁。准备倒计时期间离开则取消开局，剩余玩家回等待。ws每10秒ping，下一轮检查未收到pong则关闭，关闭后马上处理离开；标签页后台不等于退出，浏览器可能节流输入但服务器仍继续。进程重启不会保存房间，不能宣传为支持断线重连。

每个连接使用D14令牌桶，输入/ready/ping/leave消耗1，create/join消耗20；无效消息也消耗基础额度，太大/二进制/版本不符/反复非法输入可关闭该连接，不影响别的房间。发送缓冲超过256KiB时停止向慢连接堆积快照并关闭该连接。重赛旧消息通过matchId隔离；同一房间的修改由服务器同一事件循环串行完成。

本机开发服务默认127.0.0.1:8787，固定路径/ws。局域网通过显式--host参数指定局域网地址或0.0.0.0，不静默修改防火墙。生产前端与WebSocket同源，同一服务托管dist并使用已有静态服务的路径拒绝规则；开发通过Vite代理/ws。只允许配置白名单Origin升级，缺失/不匹配Origin拒绝；不得对任意Origin开放当前机器上的控制接口。Origin是基础来源校验，房间码不是账号认证。

异地联网阶段需要用户选定可运行Node的服务器并配置HTTPS/WSS；本轮不租机器、不购买域名、不部署。GitHub仓库和GitHub Pages不能替代本方案所需的常驻Node服务。使用者操作目标仍是“双击启动、浏览器打开、分享房间码”，但异地玩家必须访问同一个可达服务地址，房间码不能穿透网络。

- [MDN WebSocket](https://developer.mozilla.org/en-US/docs/Web/API/WebSocket)：浏览器原生双向连接；同步频率与预测方案是本项目设计。

## C32 已实现API与C33接入要求

- `src/sim/duel-flight.ts`：createDuelFlight(roundId=1)、advanceDuelFlight(state, [input0,input1], collider)、resetDuelRound(state,newRoundId)。固定60Hz，不接受客户端dt；返回state/events/deadSlots，输入/状态不变。advanceDuelMotion是同一运动/盾反弹逻辑的客户端预测入口，不替代服务端命中结算。输入seq=0仅用于服务器中性/保持帧，绝不能放宽D14对客户端seq>=1的校验。
- `src/sim/duel-collision.ts`：decodeDuelCollision(ArrayBuffer)或createDuelCollider(positions,indices)；sweepSphere(start,end,radius)返回最早接触比例、三角面接触点和向外法线。radius=0是双面线段遮挡，radius>0同时检测面、边和角；不是以大包围盒代替船体。
- `public/collision/venator-duel.bin`：DUELCOL1小端二进制，53026顶点、91576三角形、1735240字节。manifest含内容/source SHA-256与范围。由`node scripts/export-duel-collision.mjs`从createVenatorModel(false,false)生成；未来渲染必须使用同一工厂参数，模型改动后重导出，完整测试会检查过期源哈希。Node用fs读入，浏览器用fetch；只在适配层做I/O。当前核心没有读取文件/网络的副作用。
- `src/shared/duel-snapshot.ts`：冻结DuelSnapshot、DuelServerMessage及状态/事件类型。向量与四元数都是数组、四元数顺序x/y/z/w，不传Three.js实例；包含occupied和ready，等待时flight=null。welcome仅发自己的slot与房间码，error不包含内部连接信息。
- `src/sim/duel-snapshot.ts`：createDuelSnapshot(room,flight,serverTick,recentEvents=[])投影公开数据，最多保留96个事件；不序列化room.members/connectionId。事件服务层应保留最近12个模拟tick，再由本函数做96条硬上限；客户端按(matchId,event.id)去重。

服务集成顺序：首次双准备触发countdown-started时createDuelFlight；playing阶段每服务器tick先推进flight一次，再把本次deadSlots交给reduceDuelRoom一次。倒计时/间歇只推进room，不推进飞行；round-started在新roundId时resetDuelRound清弹、恢复两机和交换出生点，不在阶段转换的同一步额外推进新阶段。首次roundId=1不调用resetDuelRound；重赛matchId变化要重新create，清输入/ack/效果窗口，不能在旧flight上reset到roundId=1。resetDuelRound保留本场tick、投射物/事件ID和最后已消费seq，避免轮间旧消息/效果复活。

advanceDuelFlight在已有死亡的状态上保持稳定，只报告现存deadSlots；消费者必须按room.phase停止飞行，不能把旧死亡再次交给新回合。serverTick由服务端自己的循环提供，不读取客户端时间。等待/更换成员时清flight=null，避免给新对手发送旧比赛画面。

C32验证包含从真实模型导出的96条射线与Three.js原始三角面结果比对、600步确定性操作，以及真实输入→运动→射击→命中→三次击毁→3分结算→重赛的无浏览器联调。这不是网络连接、画面观感、真实设备帧率或真人对战平衡验收。

## C34 客户端已实现

src/app/duel下client.ts使用原生WebSocket，采样按单调时钟累计60Hz、每两帧发送一次，不依赖渲染帧率；预测使用同一advanceDuelMotion，快照按真实ack丢弃已确认帧并重放，最多120条未确认输入。对手采用100ms快照缓冲，最多100ms外推；阶段/轮次变化清缓存，断开停止输入，队列拥堵时短暂等待重同步，不改服务器裁判。

scene.ts使用同参数舰体工厂与蓝/红Eta-2，双尾焰、盾、实弹和有界效果/音效；追尾镜头有舰体检测和侧上方候选，避免盾反弹后镜头穿舰。start.ts提供房间码/双方准备/比分与剩余时间/重赛/退出、边缘HUD、金色激光提前量、对手方向和遮挡提示。鱼雷文字在右下角，中央仅细准星/目标框；结算隐藏武器HUD，轮间不提示可发射。Esc菜单与失焦立即发中性操控，不暂停服务端，原单人暂停行为不变。

开发QA仅在DEV且显式qa=1时暴露__duelQA，可读取快照与设置测试操控，不改血量/比分/服务器时间。生产即使qa=1也没有该钩子。两个页面已实际验证入房/准备/射击/护盾/计分/退出；不能将同机双页面等同于两名真人或两台设备实测。
