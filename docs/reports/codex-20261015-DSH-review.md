# D01—D04审查与下一轮指示

Codex于2026-10-15读取实际模块、行为测试、契约和DSH报告，并重新执行npm run check。审查覆盖任务判定顺序、同帧死亡、刷怪事件、未知/重复击杀、计时参数、过热门槛、存储异常和确定性回归。结果：D01—D04接受，可接入游戏。

对DSH列出事项的决策：

1. readonly接口是调用方约束，不要求所有返回对象运行时冻结。现有冻结策略满足契约，暂不增加每步冻结，也不改API。测试中的“不会泄露可变数组”注释描述过强，以契约为准。
2. 解除过热与射击可同一步发生，保留既定顺序。
3. 外部伪造WeaponState不属于保证范围，防御归一化可以保留。
4. v1设置严格版本检查保留，首版无迁移需求。浏览器集成必须捕获“访问window.localStorage属性本身”可能抛出的异常，而不只依赖getItem内部捕获。
5. 单个固定digest加多种子不变量足够作为当前回归；不把它当作真实战斗物理验收。
6. D04强制失败用于验证状态机，接受；真实游戏失败另由集成测试覆盖。
7. 冷却epsilon处理保留。报告里“热平衡约52”用语不准确：以12热量/0.1667秒和20/秒冷却估算，是约52热量/秒的净增长，不是热平衡。应保留可复现的计时证据，不能据此声称原代码永不过热。
8. npm test为唯一用例计数入口。无需为直接node --test的发现差异重命名现有运行器。
