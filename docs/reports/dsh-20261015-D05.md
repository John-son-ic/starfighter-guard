## 实现行为

公共接口与任务书一致：

```ts
createFrameStats(capacity = 300): FrameStats
FrameStats.push(milliseconds: number): void
FrameStats.summary(): FrameSummary        // { count, meanMs, p95Ms, maxMs, fps }
FrameStats.reset(): void
```

- **容量**：默认 300；必须为 1..10000 的整数，否则抛 `RangeError`。内部用 `Float64Array` 环形缓冲，只保留最新 capacity 条样本，`count` 不超过 capacity。
- **push**：仅接受有限正数；`0`、负数、`NaN`、`±Infinity`、字符串、null、undefined、对象、数组、布尔一律静默忽略，且不改变已有窗口。
- **summary**：不修改历史，每次返回新快照对象；空样本时五个字段全部为 `0`（不产生 `NaN`，也不返回 `-0`）。
- **统计口径**：`meanMs` = 算术平均；`maxMs` = 最大值；`p95Ms` 用升序排序后的 nearest-rank，秩为 `ceil(n × 0.95) - 1`；`fps = 1000 / meanMs`。
- **reset**：清空窗口，之后从空状态重新累计；重复调用安全。
- 多实例互相独立；模块只在调用方 `push` 时读取数值，不依赖真实时钟。

## 用例覆盖（14 项，对应任务书验证项）

| 任务书验证项 | 用例 |
| --- | --- |
| 固定样本均值/p95/max/fps | mean, max and fps match the documented formulas／p95 uses nearest-rank and stays inside the sample range |
| 容量溢出正确淘汰最旧记录 | a capacity overflow evicts the oldest samples／samples older than the window never leak back in／the default capacity is 300 |
| 无效值 | invalid samples are ignored without corrupting the window／capacity must be an integer in 1..10000 |
| 空值与 reset | an empty history reports zeros, not NaN／reset clears the window and the stats start over |
| 多实例独立 | separate instances keep independent histories |
| summary 不能污染内部数据 | summary returns a snapshot that cannot pollute internal data／repeated summary calls do not reorder or lose samples |

补充：容量 10000 的满窗口、以及一组 60fps/30fps/单次长卡顿的混合样本的形状自洽检查（`p95Ms >= meanMs`，且由均值导出的 `fps` 不低于 p95 帧所隐含的帧率）。

**p95 口径的边界值已固定**：n=1..10 时 nearest-rank 取到最大值（n=10 → 秩 9 → 第 10 个值）；n=19 → 秩 18 → 第 19 个值；n=20 → 秩 18 → 第 19 个值；1..100 → 95。这些用例同时断言 `p95Ms !== maxMs`（1..100 时），防止 p95 退化成最大值。

## 已知问题

1. `p95Ms` 的秩计算依赖浮点乘法 `Math.ceil(n * 0.95)`。在极端 n 下若 `n * 0.95` 恰好落在整数边界，浮点误差理论上可能使秩偏 1。已用 n=10、19、20、100 固定当前行为；若 Codex 认为需要整数运算（如 `Math.ceil((n * 95) / 100)`）应明确口径，DSH 未擅自更改任务书给定的公式。
2. 内部样本用 `Float64Array` 存储，`push` 会把入参按 IEEE754 双精度写入；对 `Number.MIN_VALUE` 量级的正数也会被接受并计入（属有限正数）。
3. `summary()` 每次调用都复制并排序整个窗口（O(n log n)，n ≤ 10000）。任务书未给性能指标，本模块也不做性能声明；若集成时每帧调用 summary，建议 Codex 降低调用频率。
