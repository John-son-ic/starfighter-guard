## 实现行为核对（定理 → 用例）

| 契约规则 | 结论 | 对应用例 |
| --- | --- | --- |
| 初态 approach，四个计数为 0，rescueCalled=false，lossReason=null | 符合 | a new mission starts in approach with every counter zeroed |
| 冻结常量：8 上限 / 24s 增援 / 60s 撤离 / 8s 救援 / 4s 入场 | 符合（并断言 8+4=12） | the frozen config still carries the numbers the contract states |
| dt 必须有限且 0≤dt≤0.1，否则 RangeError | 符合（10 组非法值） | illegal dt is rejected with RangeError before any state change |
| activeEnemies 必须 0..8 整数，否则 RangeError | 符合（9 组非法值，0..8 全通过） | activeEnemies must be an integer in 0..8 |
| approach 需 patrolCleared 且 inStationRange 才进 facilities，checkpoint 一次 | 符合 | approach only leaves for facilities…／the facilities checkpoint is reported exactly once |
| 只毁一个设施不进入 reactor | 符合 | either facility alone never exposes the reactor |
| 两设施都毁 → reactor，同帧输出 reactor-exposed + checkpoint reactor | 符合，且一次只转一个阶段 | destroying both facilities exposes the reactor once… |
| 同帧三目标全毁也不跨到 escape | 符合，停在该步的 reactor | both facilities plus the reactor in one step stops at reactor… |
| 24s 增援，每次最多 2 机，不超 8 | 符合 | reinforcements arrive at 24 seconds…／a single step never back-fills… |
| 满员也重置本次计时 | 符合（无 spawn 事件，计时归零） | reinforcement never pushes the field past the 8 enemy cap |
| 通讯被毁立即停止增援计时 | 符合（冻结而非清零） | destroying comms stops the reinforcement clock… |
| 通讯恢复后是否续计（契约未明写） | 实测从冻结值续计 | the reinforcement clock resumes from its frozen value… |
| 计时到期当步通讯已被毁则不补机 | 符合 | destroying comms while the timer is past due emits nothing on that step |
| 反应堆毁 → escape，phaseTime=0，escape-started，追击机补足 4（≥4 不新增） | 符合（0→4、1→3、3→1、4/5/8→无事件） | destroying the reactor starts escape…／pursuers top the field up to four… |
| escape 从进入后的下一步开始计时 | 符合（进入步 phaseTime=0，下一步=dt） | escape does not tick on the entry step… |
| 第 8 秒 rescue-arrival 一次，rescueCalled=true | 符合，且只发一次 | escape does not tick on the entry step…／the rescue arrival boundary is inclusive… |
| 第 12 秒起且 atExtraction 才 won；提前到达不胜利 | 符合（12s 前即使一直 atExtraction 也不胜） | winning requires extraction at or after 12 seconds／the 12 second boundary is inclusive |
| 第 60 秒超时优先，lossReason=escape-timeout | 符合；**恰在 60 秒到达也判超时** | the escape window times out at 60 seconds／arriving exactly at the 60 second mark still times out |
| 玩家死亡优先，任何阶段不被同帧成功条件覆盖 | 符合（四个阶段各验一次，事件为空） | player death wins every same-frame race…／death beats a would-be win on the exact winning step |
| 终态稳定且不重发事件 | 符合（返回同一 state 对象，events 为空） | terminal phases are stable and never re-emit events |
| phaseTime 仅在转换时归零，elapsed 累计 | 符合（转换后 phaseTime=0 且 elapsed 递增；两条失败路径现已一致归零） | elapsed accumulates while phaseTime restarts at each transition／both loss paths zero phaseTime |
| dt=0 可处理状态条件但不推进时间 | 符合 | dt=0 can advance a phase condition but never advances time |
| 输入与 state 均不被修改 | 符合（冻结输入可用，state 原值不变，返回新对象） | inputs and states are never mutated |
| 不使用实际时间、随机全局、DOM、Three.js、网络、sleep | 符合（源码扫描 + 唯一 import 为 relay-contract） | the module stays a pure state machine with no clock, DOM or randomness |
| 同种子确定性、有界长序列（≤100000 步） | 符合（三次运行 38/38 稳定） | identical seeds produce identical traces／a long bounded sequence… |

## 已知问题（供 Codex 决策，DSH 未改代码）

1. ~~两条失败路径的 `phaseTime` 处理不一致~~ —— **已在执行期间由 Codex 修复**（玩家死亡分支现也置 `phaseTime: 0`，mtime 21:53:13）。现已新增断言固定「两条失败路径都归零」，作为回归保护。若该统一不是有意为之，请告知，我会改为按契约原文只断言阶段与原因。
2. **`reinforcementTime` 在每次阶段转换时也被归零**，而契约只规定 `phaseTime=0`。对玩法无影响（进入新阶段本就该重置增援节奏），仅记录为契约未提及的额外重置。
3. **校验顺序为 dt → activeEnemies → 终态判断**，因此**终态下传入非法 activeEnemies 仍抛 RangeError**。这符合契约「校验无条件、终态**有效输入**后稳定」，但调用方若期望终态吞掉坏输入会意外；已有用例固定该行为。
4. **reactor 阶段的增援计时分支在正常玩法中不可达**：进入 reactor 的前置是两设施皆毁（含通讯），因此通讯必为已毁、增援永不触发。契约仍要求「reactor 仍按同样通讯规则判断」，故用**人工构造的 reactor state** 覆盖该分支（1 个用例），并在用例名中注明。若 Codex 认为不应测不可达状态，可删除该用例，不影响其余 38 项。
5. **满员时增援到期的可观察结果是「无 spawn 事件 + 计时归零」**，没有零数量事件。这符合「满员也重置本次计时」，但 HUD 若想提示「本波未到」需自行判断计时归零。
6. 边界判定统一带 `+1e-9` 容差，故 8s/12s/24s/60s 均为**含等号**。若 Codex 希望改为严格大于，需同步改实现与用例。
7. `input` 为 `undefined` 时抛 `TypeError` 而非 `RangeError`（读取 `input.activeEnemies`）。契约只规定字段非法时抛 RangeError，未规定整个 input 缺失；记录为调用方责任。
