### 安全实现

`resolveRequestPath(root, pathname)` 按顺序拒绝：空值、NUL、原始反斜杠 → `decodeURIComponent`（失败即拒绝，覆盖坏百分号编码）→ 解码后再查 NUL/反斜杠/**冒号**（盘符与 NTFS 数据流）/`//` UNC 前缀 → `resolve(join(root, decoded))` → 段前缀包含性检查 → `realpathSync` 解析符号链接后再做一次包含性检查（目标不存在时返回未解析路径，交由 404 处理）。

**实现过程中发现并修掉的两个自身缺陷：**

1. **默认根目录请求被误判为越界。** 最初用 `normalize(join(root, '/'))`，在 Windows 上会保留结尾分隔符（`...\dist\`），导致它与 `root` 字符串不相等、被包含性检查判为越界，`/` 与 `/?mode=models` 全部返回 403。改为 `resolve()` 归一化后再比较。
2. **盘符检查写错方向。** 最初用 `/^[a-zA-Z]:/` 只匹配**开头**的盘符，而请求是 `/C:/Windows/win.ini` 这种以斜杠开头的形式，可直接绕过。改为拒绝路径中任何位置的冒号。

这两个缺陷都是靠测试暴露的，不是靠读代码发现的。

## 已知问题

1. **不记录访问日志。** CLI 只打印启动横幅，不逐请求打印。任务书未要求，但排查“某个资源 404”时不如 Vite 方便。
2. **只映射目录自身的 `index.html`**，不做 SPA 式回退（`/任意路径` → `index.html`）。这是任务书明确要求（缺失资源返回 404），对当前无前端路由的构建没有影响。
3. `cache-control` 设为 `no-cache`，便于本地更新构建后立刻生效；未做 ETag/Last-Modified。本地工具场景足够，未扩展。
4. 端口占用后不会自动改端口，只提示 `--port` 用法。按任务书要求“不结束其他进程”，且未要求自动重试。
5. CLI 的 `--help`/未知参数一律按非法参数处理（退出码 2 并打印用法），没有单独的帮助页。
