## 实现行为

- createMission：验证 config（waves 非空且每项为 1..maxActiveEnemies 的整数、maxActiveEnemies 为正整数、两项时长为有限非负数），非法输入抛 RangeError；返回 briefing、waveIndex=-1、空 activeEnemyIds、三个计数为 0、lossReason=null。
- advanceMission：先验证 config 再验证 dt（有限且 0..0.1），验证失败抛 RangeError 且不触碰 state；随后固定顺序执行——终态原样返回空 events → playerAlive=false 优先判 player-destroyed，否则 carrierAlive=false 判 carrier-destroyed（立即 lost、单个 mission-lost、不计时/不计杀/不刷怪）→ 累计 elapsedSeconds 与 phaseSeconds → combat 仅移除当前 activeEnemyIds 中的 destroyedEnemyIds（未知/重复/旧波 ID 忽略，同一 ID 最多计一次 kills）→ combat 清空则最后一波 won（一次 mission-won），否则进入 intermission 且 phaseSeconds 置 0 → briefing/intermission 到时生成下一波，每步最多一次转换、余量舍弃。
- 敌机 ID：`wave-{一基波号}-enemy-{一基序号}`。spawn-wave.enemyIds 与 state.activeEnemyIds 内容一致但为独立冻结副本；spawn 当步不处理 destroyedEnemyIds。
- 无事件时 events 为 []，不重复发送上一帧事件；暂停由调用者停止调用实现；零时长 briefing 可在 dt=0 启动。

## 用例覆盖（20 项，对应队列必测项）

| 队列必测 | 用例 |
| --- | --- |
| 首波到时只生成一次 | briefing spawns the first wave exactly once, at the scheduled time |
| 波内部分击杀 | partial kills keep the wave alive and only count listed, active IDs |
| 重复/未知/旧波ID | 同上 + IDs from an earlier wave cannot kill the current wave |
| 间隔不提前刷怪 | the intermission waits the full configured delay and spawns only then |
| 每次刷新符合上限 | every spawn respects the wave table and the active-enemy cap |
| 三波清完胜利 | clearing the third wave wins exactly once with the final kills recorded |
| 玩家/母舰失败 | player death…／carrier death… |
| 同帧失败优先 | the same step that clears a wave and kills the carrier is a loss, not a win |
| 终态幂等 | a lost mission is terminal and idempotent, including dt=0 |
| dt=0 | dt=0 processes damage without adding time, and zero-second phases start at dt=0 |
| 非法dt/config | createMission rejects illegal configs／advanceMission rejects illegal dt before touching state |
| 输入不被修改 | frozen config and inputs are never modified |
| 两局不串数据 | two missions started from the same config never share state |

补充：创建初始状态、事件一次性与不重复、briefing 与 intermission 同一余量策略、spawn 当步不计杀、敌机 ID 唯一性与生成顺序。

## 环境限制（已解除，保留记录供复现）

本轮最开始时文件策略为 workspace-write，直接运行 `npm run check` 时构建阶段失败：

```text
Error: Build failed with 1 error: [plugin externalize-deps] Error: spawn EPERM
  at optimizeSafeRealPathSync (vite/dist/node/chunks/node.js)
```

原因：Vite 在 Windows 上通过 `exec('net use')` 解析真实路径，受限策略禁止其子进程管道；`node --test` 同样因测试运行器 spawn 子进程失败。两者与本任务代码无关。

会话中途文件策略改为 danger-full-access 后，标准命令 `npm run check` 连续多次退出码 0，无需任何包装参数，本报告的正式结果即取自该状态；本轮末（D04 完成后）再次确认退出码 0。若其他机器仍处受限策略，可用 `NODE_OPTIONS=--experimental-test-isolation=none` 让测试步骤在同一进程内运行，构建步骤需能 spawn 子进程。

## 已知问题

1. `activeEnemyIds` 返回普通（未冻结）数组。types.ts 标注为 readonly，运行时不冻结；与 createMission、spawn-wave.enemyIds（已冻结）不一致。契约只要求「外部调用方不得修改」，未要求冻结，因此未单方面改变冻结策略，留给 Codex 决定是否统一。
2. 零时长 briefing 与 dt=0 时，`phaseSeconds` 不会因 spawn 累积，符合「时间余量舍弃」的契约；但契约未写明 dt=0 的 briefing 是否应视为「到时」，本实现按 `phaseSeconds >= briefingSeconds` 判定，0>=0 成立即启动，已在用例中固定该行为。

## Codex 审查结论（2026-10-15，见 docs/reports/codex-20261015-DSH-review.md）

D01 已被接受。

- 对已知问题 1 的决策：**readonly 是调用方约束，不要求所有返回对象运行时冻结；现有冻结策略满足契约，暂不增加每步冻结，也不改 API。** 因此本项不再作为待办遗留问题，而是已被接受的设计选择。
- 依据该决策，已把 tests/dsh/mission.test.mjs 中原「不会泄露可变数组」的过强注释改为准确表述（readonly 是调用方契约、返回数组是独立对象且不复用调用方数组），断言本身未改弱。
