## 实现行为

- applyDamage：health/damage 必须有限且非负，否则 RangeError；返回 max(0, health - damage)。不做命中检测、护盾或击杀统计。
- createWeapon：返回 heat=0、cooldownSeconds=0、overheated=false 的新对象。
- advanceWeapon：先验证 config（maxHeat/heatPerShot/coolingPerSecond/shotIntervalSeconds 有限且>0，heatPerShot<=maxHeat，unlockHeat 有限且在 [0,maxHeat)），再验证 dt（有限且 0..0.1）。顺序为：按 dt 冷却热量至不小于 0 并递减 cooldown → 原 overheated 且 heat<=unlockHeat 则解除过热 → triggerHeld 且未过热且 cooldown 为 0 时只发射一次，heat 增加 heatPerShot 并截断到 maxHeat，cooldown 置 shotIntervalSeconds，heat 达到 maxHeat 立即过热（该次射击有效）。每调用最多一次射击，不追补间隔内子弹；不射击也冷却。
- `triggerHeld` 仅接受布尔 true；其他值按未按住处理。

## 实现中发现并修复的数值缺陷（D02 内）

**冷却余量未被吸收导致射速随帧率漂移。** 原实现用 `cooldownSeconds === 0` 判断武器就绪。0.15 秒冷却按 1/60 固定步递减 9 次后余下 2.08e-17，不等于 0，于是每发子弹被推迟整整一帧。

**可复现的计时证据**（Node v24.16.0，1/60 固定步，按住扳机。修复前数据由逐行复刻旧的严格 `=== 0` 判定、在独立脚本中重放取得）：

| 观察项 | 修复前 | 修复后 |
| --- | --- | --- |
| 前 60 步内的射击步号 | 0、10、20、30、40、50 | 0、9、18、27、36、45、54 |
| 前 60 步内射击次数 / 结束时热量 | 6 / 52.33 | 7 / 64.33 |
| 前 70 步内射击次数 / 结束时热量 | 7 / 61.00 | 8 / 73.00 |
| 实测射击间隔 | 10 步 = 0.1667 秒 | 9 步 = 0.15 秒（与 `shotIntervalSeconds` 一致） |
| 首次进入过热的步号（及其为第几发） | 110（第 12 发） | 90（第 11 发） |

**结论限于上述计时数据**：修复前有效间隔被拉长到 0.1667 秒，升温更慢——每发净增热量约 `12 - 20 × (1/60) ≈ 11.67`，而按 0.1667 秒计每发平均冷却约 `20 × 0.1667 ≈ 3.33`。**它仍会过热，只是比修复后晚一发、慢约 20 步**（第 12 发 / 第 110 步，对比修复后的第 11 发 / 第 90 步）。因此本报告不声称原代码永不过热，只保留上表可复现的步号与热量数值；Codex 审查指出原「热平衡约 52」用语不当——52.33 只是第 60 步的瞬时热量，不是平衡值。

修复：新增模块内常量 `COOLDOWN_EPSILON_SECONDS = 1e-9`，在递减后把低于该值的冷却归零，再做就绪判断。修复后实测射击落在第 0、9、18、27、36… 步，间隔恒为 9 步；按住扳机在第 11 发（第 90 步）达到 100 热量并进入过热。该修复不改变公开 API，也不放宽任何校验。

## 用例覆盖（16 项，对应队列必测项）

| 队列必测 | 用例 |
| --- | --- |
| 伤害归零 | applyDamage subtracts and clamps at zero |
| 零伤害 | 同上（applyDamage(100,0)=100；applyDamage(0,0)=0） |
| 非法数值 | applyDamage rejects illegal numbers（含负数、NaN、Infinity、字符串、undefined） |
| 首次射击 | the first trigger pull fires once and re-arms the cooldown |
| dt=0 连发不绕过冷却 | dt=0 fires a ready weapon but cannot bypass the cooldown |
| 按住射击达到过热 | holding the trigger overheats the weapon |
| 未到阈值不解锁 | an overheated weapon stays locked until heat reaches the unlock threshold |
| 冷却到阈值恢复 | the unlock threshold is inclusive and can fire in the same step |
| 松开扳机冷却 | releasing the trigger cools heat and re-arms the weapon |
| 输入对象不变 | configs, states and shared defaults are never modified |
| 长期状态保持有限且热量范围合法 | long held-trigger sequences…／heat cycles and never accumulates unbounded… |

补充：不追补间隔内子弹（a step never back-fills skipped intervals）、每步最多一次射击、两把武器互不共享、非法 config/dt 在改动状态前拒绝。

## 已知问题

1. `advanceWeapon` 对来自外部的异常 state 字段做钳制而非报错（非法 heat 归 0、超上限 heat 截断到 maxHeat、负 cooldown 归 0、非 true 的 overheated 视为 false）。契约说明「初始 state 假设来自本模块」，因此该行为属防御性归一，未扩大公共 API；若 Codex 希望严格报错需修改契约。
2. 解过热与射击可在同一步发生（heat 降到 unlockHeat 以下且 cooldown 已耗尽时）。契约措辞为「若原来 overheated 且热量<=unlockHeat 则解除过热」后接射击判断，本实现遵循该顺序；若期望至少延迟一帧才能开火，需要 Codex 明确契约。
