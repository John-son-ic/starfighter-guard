## 实现规则（对照任务书）

导出 `decodeDuelClientMessage(text)`、`createDuelMessageBudget(nowMs)`、`consumeDuelMessageBudget(state, nowMs, cost?)`；类型来自共享契约。

**消息解码**

- `text` 运行时非 string → TypeError。
- 先按 **UTF-8 字节数**比较 `DUEL_NET.maxMessageBytes`（8192），超出 → `{ok:false, error:'too-large'}`；**等于 8192 仍进入解析**。使用全局 `TextEncoder`，不用 Buffer、不引入 `node:*`。
- 长度检查先于 `JSON.parse`；解析抛错 → `bad-json`。
- 合法 JSON 但不符合 schema → `invalid-message`：不抛异常、不补默认值、不强转、不丢额外字段（一律拒绝）。
- 每个对象用 `Object.getOwnPropertyNames` 取自有键并与该消息的完整字段集**精确比对**：缺字段与多字段都拒绝。只读取已知键，绝不把原型上的值当字段。
- 根必须是普通对象：null、数组、数字、字符串、布尔都拒绝。
- `v` 必须是数字 1；未知/缺失/非字符串 `type` 拒绝。
- create/leave：恰有 `v`/`type`。join：+`code`，规则同 D13（6 位、`DUEL_ROOM_ALPHABET`、不 trim、不转大小写）。ready：+`value`，严格 boolean。ping：+`nonce`，整数 0..2147483647。
- input：恰有 `v`/`type`/`matchId`/`roundId`/`frames`；matchId、roundId 为 1..2147483647 整数；frames 长度 1 或 2。
- frame 恰好 9 个字段：`seq` 为 1..2147483647 整数；`yaw`/`pitch`/`roll`/`throttle` 为有限数且 -1..1；`boost`/`fire`/`torpedo`/`shield` 严格 boolean。
- 同包两帧 seq **严格递增**，允许不连续；跨包旧 seq 与 match/round 不符由 Codex 服务层拒绝——解码器不持有会话状态。
- 成功返回全新构造的 `DuelClientMessage`（含新数组、新 frame 对象），与入参和被解析对象无共享引用。
- 不实现服务端消息解码、不创建连接、不含 connectionId/位置/命中/时间步字段。

**纯令牌桶**

- `createDuelMessageBudget(nowMs)`：nowMs 有限且 >=0，否则 RangeError；初态 `tokens=bucketCapacity(120)`、`lastMs=nowMs`。
- `consumeDuelMessageBudget(state, nowMs, cost=1)`：nowMs 有限且 >= `state.lastMs`，否则 RangeError；cost 省略为 1，否则必须 1..120 整数，否则 RangeError；非法输入不修改 state。
- `available = min(120, tokens + (nowMs - lastMs) * 60 / 1000)`；`available + 1e-9 >= cost` 允许，`tokens = max(0, available - cost)`，否则 `tokens = available`；两种情况 `lastMs = nowMs`。不四舍五入、不修改输入、返回新对象。
- 无计时器、无等待、无封 IP、无消息解析：模块只接受 cost。

**33 个用例分组**

1. 合法消息（3）：六种消息各自的精确重建；单帧/双帧/seq 间隙/轴边界 ±1；房间码字母表（含小写、含 0/1/I/O、5/7 位、空白、null、数字）。
2. 版本与类型（2）：缺失/0/2/"1"/true/null；snapshot、welcome、spawn、hit、state 等未知 type、空 type、大小写变体、数字/null type。
3. 字段完整性（3）：缺字段与多字段逐一拒绝；禁止携带 position/hit/victimId/damage/connectionId/serverTick/dt/health/score；根为 null/数组/字符串/数字/布尔/空对象。
4. 类型严格性（3）：boolean 不 coercion（0/1/"true"/null）；数字不收字符串、不收小数；1e999 溢出为 Infinity 被拒，字面 NaN 属坏 JSON。
5. 序列规则（3）：seq 为 0/-1/-100 拒绝；包内降序、相等、重复拒绝；seq 超出上限拒绝；matchId/roundId 为 0/负数/超上限拒绝，上限值可用。
6. frames 约束（2）：0 帧、3 帧、非数组拒绝；frame 缺任一字段、多字段、null/数组/字符串拒绝。
7. 原型污染（1）：`__proto__`/`constructor`/`toString` 作为自有键按额外字段拒绝（join 与 frame 两处），并确认 `Object.prototype` 未被污染。
8. UTF-8 长度（2）：恰 8192 字节进入 schema 校验、8193 → too-large；2800 个中文字符（字符数 < 8192、字节数 > 8192）判 too-large，缩到 2000 个中文字符则进入 schema 校验。
9. JSON 与参数（2）：10 种畸形 JSON → bad-json；非 string → TypeError。
10. 解码隔离（1）：两次解码返回互不相同的对象与数组且内容相等；改动一次结果不影响下一次解码。
11. 令牌桶（8）：构造与初值；非法 nowMs；默认 cost=1 与耗尽；60/秒补充与 120 封顶；20ms 精确恢复（1.2 令牌）、1e-9 容差、明显不足被拒；拒绝仍推进 lastMs 并保留补充量；成本 20 的准入（120 令牌恰好 6 次）；非法 cost/时钟倒退不修改 state；同一时间戳合法且不补充；两连接独立；返回新对象且不改输入。

## 开发过程中修正的自测缺陷

首次运行有 2 项失败，均为**测试预期错误**，实现未改动：

1. 我把 `{"v":1.0,...}` 写进了「应拒绝」列表。JSON 只有一个数值类型，`1.0` 与 `1` 解析为同一 number，因此实现接受它是正确的；已改为断言「1.0 与 1e0 均视为 1」。
2. 满桶时我预期 `120 + 0.6 - 20 = 100.6`。按契约公式 `available = min(120, tokens + refill)` **先封顶再扣费**，满桶的亚秒补充会被丢弃，正确结果是 `100`；已改为断言 100，并另加「未满桶时 0.6 补充生效」的对照。

## 已知问题（需 Codex 定夺或知悉）

1. **`createDuelMessageBudget` 的错误类型由我选取。** 任务书对该构造函数只写「nowMs 为有限且 >=0 的数」，未指明错误类型；`consume` 明确为 RangeError。为保持一致，构造函数也用 RangeError。若服务层希望 TypeError 或返回结果对象，请明确。
2. **满桶的亚秒时间不计入令牌。** `available` 按容量封顶后再扣 cost，因此 `tokens=120` 时任何 `0 < Δt < 1/60 秒` 的补充都会被丢弃（严格按任务书公式）。影响：满桶连续扣费时，补充起始点在每次扣费后重新计算，最多损失不足一个令牌。若希望「先扣费再封顶」，需改公式。
3. **服务端需要自己限制入站包大小。** 解码器为保证字节语义会对整段文本执行 `TextEncoder.encode`；若上游允许超大帧，内存会随之增长。设计要求 `ws` 的 `maxPayload=8192` 已在上游兜底，解码器不额外截断。请确保服务端保留该设置。
4. **`consume(state, t, undefined)` 视为「省略」。** 默认参数把显式 `undefined` 也当作省略（cost=1），与任务书「cost 省略为 1」一致；但若服务层希望显式 undefined 报错，需要改签名语义。
5. **重复 JSON 键取最后一个。** 如 `{"v":1,"v":1,...}` 由 `JSON.parse` 决定（标准行为），解码器未额外拒绝原文中的重复键；要做到需先扫描原文，不建议。
6. **`1.0`/`1e0` 等同 `1`。** 见上「自测缺陷 1」；JSON 无法区分字面量形式。
7. **解码器无会话状态。** 跨包旧 seq、matchId/roundId 不匹配、输入队列上限、250ms 输入超时都需要 Codex 服务层拒绝/处理，本模块按要求不做。
8. **不改契约的前提下，非字符串 `text` 抛 TypeError 而非返回 `bad-json`。** 这是任务书明确要求的（运行时非 string 抛 TypeError）。
