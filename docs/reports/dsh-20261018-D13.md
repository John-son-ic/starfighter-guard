## 实现规则（对照任务书）

导出 `createDuelRoom(code)` 与 `reduceDuelRoom(state, command)`，类型全部来自共享契约。

**初态与校验**

- code 必须恰 6 位且全部属于 `DUEL_ROOM_ALPHABET`；不 trim、不转大小写；否则 RangeError。
- 初态：`waiting`、`members=[null,null]`、`scores=[0,0]`、matchId/roundId/phaseTicks/matchTicks 全 0、winner/finishReason 为 null。
- connectionId 必须匹配 `^[A-Za-z0-9_-]{1,64}$`；ready.value 严格 boolean；leave.reason 仅 leave/disconnect；tick.deadSlots 长度 0..2、元素 0/1、不重复。运行时字段非法 → RangeError。
- 未知 command.type（含缺失、非字符串）→ TypeError。校验先于终态判断，因此终态房间收到畸形命令仍抛错。

**join / ready / leave**

- `closed`：有效 tick 稳定返回；其余有效命令 → `room-closed`。
- join 判定顺序固定为 重复 → 满员 → 阶段：`already-member` → `room-full` → `room-busy`（仅 waiting/finished 允许）。取最小空槽；成功清双方 ready。
- finished 中 join：回 `waiting`，清零 scores/roundId/phaseTicks/matchTicks/winner/finishReason，保留 matchId。
- ready：非成员 `not-member`；非 waiting/finished 为 `not-ready-phase`；同值不产生事件且返回同一 state；两人均 ready 时 matchId+1、roundId=1、phase=countdown、清零其余，输出 `countdown-started`，两人 ready 保持 true。
- leave：非成员 `not-member`；先移除并清双方 ready，输出 `member-left(slot)`。无人剩余 → `closed` + `room-closed`，保留比分与结果，不产生 match-finished。
- waiting/countdown 离开且有人：回 waiting，比分/roundId/计时清零、winner/finishReason=null，保留 matchId，取消开局。
- playing/intermission 离开且有人：`finished`，winner=剩余槽，finishReason=command.reason，phaseTicks=0，比分不变，member-left 后输出一次 match-finished。
- finished 离开且有人：保持 finished 与结果，不重发 match-finished。

**tick / 回合与整场**

- waiting/finished/closed 的有效 tick 完全 no-op（返回同一 state）。
- countdown/intermission 忽略 deadSlots。
- countdown：phaseTicks+1，恰到 180 → playing、phaseTicks=0、`round-started(roundId=1)`，matchTicks 仍 0，且该步不再推进 playing。
- playing：phaseTicks 与 matchTicks 各 +1。`[0]` → 槽 1 得分，`[1]` → 槽 0 得分，双死不加分。有死亡输出 `round-ended`（winner 为获分槽，双死为 null，deadSlots 为升序新数组）。
- 判定顺序：先看是否有人达 3 分（finishReason=score），再看 matchTicks>=36000（按更新后的比分定胜负，同分 winner=null，finishReason=time-limit）。整场结束时 phaseTicks=0、清双方 ready、输出一次 `match-finished`。同 tick 双结束的事件顺序为 `round-ended` → `match-finished`；仅超时则只有 `match-finished`。
- 有死亡但整场未结束：intermission、phaseTicks=0、保留 matchTicks、roundId 不变；后续 intermission tick 不重复计分。
- intermission：phaseTicks+1、不累加 matchTicks；恰 300 → playing、roundId+1、phaseTicks=0、`round-started(新 roundId)`。
- 时间全部为整数 tick，不接受 dt/毫秒/Date；无 DOM、Three.js、网络、时钟、计时器、随机。

**不变量**：输入 state 与 command（含嵌套数组）不被修改；业务拒绝返回原 state、空 events 与 error；成功 error=null；events 只属于本次调用。

2. 命令校验（5）：id 长度与字符集（含 64 位上限、非 ASCII）；ready.value 各种非布尔；leave.reason 各种非法；deadSlots 13 种非法形状；未知 type → TypeError；终态仍先校验。

6. 回合与计分（4）：计时累加；单死给幸存者加分；双死平局且 deadSlots 升序、不重排调用方数组；非 playing 阶段忽略 deadSlots。
7. 间歇（2）：300 tick 内不重复计分、不累加 matchTicks；恰第 300 tick 开下一轮并 roundId+1。
8. 整场结束（4）：3 分胜利；36000 临界按比分定胜负；同分平局；最后一 tick 得 3 分优先于超时；超时且有死亡时事件顺序正确。
9. 离开（4）：倒计时离开取消开局；战斗中 leave/disconnect 判负；结算后离开不重发 match-finished；最后一人离开关闭房间并保留比分。
10. 重赛与隔离（3）：新成员加入已结算房间清结果并保留 matchId、清双方 ready；重赛 matchId+1；两独立房间无串数据。
11. 终态与长序列（2）：waiting/finished/closed 的 tick 完全 no-op；601 tick 的有界真实推进序列状态自洽。

## 已知问题（需 Codex 定夺或知悉）

1. **`deadSlots=[0]` 的语义解读。** 任务书原文「`=[0]`给1号一分，`=[1]`给0号一分」。本实现取「槽位号」读法：0 号槽阵亡 → **1 号槽得分**（`scores[1]+1`，`round-ended.winner=1`）；1 号槽阵亡 → 0 号槽得分。这与同句「winner 为该回合获分 slot」以及「死者不能得分」一致。若原文意在「给 1 号玩家（P1=槽0）加分」，则语义相反，请明确。
2. **离开导致的 finished 不重置 matchTicks。** 契约对该分支只规定 `phaseTicks=0`（未提 matchTicks），本实现保留其原值；`scores` 与 `roundId` 同样不变。若希望离开时也清零，请改契约。
3. **构造状态中双方均 ≥3 分的不可达分支。** 正常流程下每 tick 至多一人加分，双方同时达 3 分不可能。若传入这种状态，本实现按槽 0 优先判胜。仅为确定性，不属契约要求。
4. **leave 会清除双方 ready（含 finished 阶段）。** 这是契约「找到则移除，清双方 ready」的直接结果：结算后一人离开，剩余者需重新准备。若希望保留剩余的 ready 标记，需改契约。
5. **`closed` 优先于所有业务错误。** 已关闭房间对任何有效非 tick 命令都返回 `room-closed`，包括「非成员 ready」。这与「closed 房间对有效非 tick 命令返回 room-closed」一致，但与「ready 先判 not-member」的顺序不同；本实现按任务书的 closed 优先条款执行。
6. **`createDuelRoom` 的 code 校验只在构造时发生。** `reduceDuelRoom` 不再复验 state.code（state 来自本模块/构造函数）。
