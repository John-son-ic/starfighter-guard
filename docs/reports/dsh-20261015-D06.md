## 接口

```js
// 可 import，import 时不触发 CLI
import { verifyAssets } from '../scripts/verify-assets.mjs';
const { modelCount, totalBytes } = verifyAssets(directory);
// 校验失败时抛出 Error，message 内含全部问题条目
// 需要收集问题而不抛出时：verifyAssets(dir, { throwOnError: false }).errors
```

CLI：`node scripts/verify-assets.mjs [modelsDirectory]`（默认 `public/models`）

- 全部通过：stdout 打印 `verified N models, B bytes`，退出码 0。
- 任一失败：逐行 stderr 输出「文件 + 原因」，退出码 1，stdout 为空，且不打印堆栈。
- 入口判定使用 `import.meta.main`（Node 24 支持），并以 `process.argv[1]` 解析路径作为回退。

## 检查项

| 类别 | 具体检查 |
| --- | --- |
| manifest 结构 | 文件存在且可读；合法 JSON；顶层为对象；`models` 为数组 |
| ID 集合 | 4 个预期 ID（venator、eta2、arc170、vulture）不缺失、不重复；出现未知 ID 报错 |
| 文件名 | 必须是裸文件名（无 `/`、`\`、`..`、`:`、首尾空白）；必须等于 `<id>.glb`；同一文件名不得重复列出 |
| 文件存在与长度 | 每个条目对应的 GLB 必须在磁盘上；manifest 的 `bytes` 必须等于实际文件长度 |
| 数值合法性 | `triangles`、`materialBatches`、`bytes` 必须是正整数 |
| GLB 容器 | magic = `0x46546C67`；container version = 2；头部声明长度等于实际文件长度；JSON chunk 长度落在文件内；首块类型为 JSON（`0x4E4F534A`） |
| JSON chunk | 可 `JSON.parse` 且为对象 |
| 面数 | 逐 primitive 按 accessor 计算：有 `indices` 用 index accessor 的 count，无 `indices` 用 POSITION count，均除以 3；非 4（TRIANGLES）模式报错；结果非整数报错；合计必须等于 manifest 的 `triangles` |
| materialBatches | 顶层（`scene` 默认 0）场景图中引用 `mesh` 的节点数（含子节点遍历、重复引用与越界引用报错）必须等于 manifest 的 `materialBatches` |

路径穿越是硬拒绝：文件名不合规时该条目直接不计入已验证模型数。测试确证 `../outside/eta2.glb`、`..\outside\eta2.glb`、`sub/eta2.glb`、`C:/tmp/eta2.glb`、`/etc/eta2.glb` 全部被拒，且针对 `../outside/` 的尝试不会读到临时目录外的文件。

## 已知问题

1. 检查按 GLB 的**声明值**计算面数，不解析二进制 bufferview/accessor 的实际数据长度，因此「accessor count 与实际 buffer 字节数不符」的坏文件不会被发现（此类文件在运行时才暴露）。任务书只要求「position/index accessor count 算得的面数」，故按此实现。
2. GLB 只校验首个 chunk 为 JSON，不强制要求 BIN chunk 存在或其长度字段自洽。任务书未要求，未擅自扩展。
3. 预期 ID 列表在脚本内以常量 `EXPECTED_MODEL_IDS` 固化（与 `src/shared/config.ts` 的 `MVP_CONFIG.models` 一致）。脚本未被允许修改 shared，因此若模型集合变化，需要同步该常量；测试中以同一列表断言，能发现不一致但不会自动跟随。
4. 文件名检查拒绝冒号，因此在 Windows 上 `C:\...` 与 `C:/...` 形式都会被拒（符合「禁止路径穿越」要求，但也会拒绝合法的绝对路径写法——本脚本只需要裸文件名，符合契约）。
5. `verifyAssets(dir, { throwOnError: false })` 返回的 `{modelCount,totalBytes}` 在失败时表示**成功校验通过的条目数**，不是清单条目数；任务书要求的抛出式接口不受影响。
