## 接口与实现

```ts
interface Intercept { point: Vec3; time: number }
solveIntercept(shooter, target, targetVelocity, projectileSpeed, maxTime = 2): Intercept | null
```

解 `|r + v·t|² = s²·t²`（r = target − shooter，v = targetVelocity，s = projectileSpeed），展开为
`a·t² + b·t + c = 0`，其中 `a = |v|² − s²`、`b = 2·r·v`、`c = |r|²`。

- 取**最早的非负根**；两个根都可能为正时取较小者。
- `a ≈ 0`（目标速率恰等于弹速）时方程退化为线性 `2·r·v·t + |r|² = 0`，直接解线性，不用求根公式；`b` 也为 0 时无解。
- 用数值稳定的求根形式：`q = −0.5·(b + sign(b)·√D)`，两根取 `q/a` 与 `c/q`，避免 `−b ± √D` 的相减抵消。
- 根计算完成后做**代回自检**：若 `|point − shooter|` 与 `s·t` 的相对偏差超过容差则返回 null，不把无法求解的结果当成命中。
- 射手与目标重合（距离 ≤ 1e-9）时返回 `time = 0` 与目标点。
- 超过 `maxTime` 返回 null（边界含等号）。
- 校验：三个向量的每个分量必须有限，`projectileSpeed` 与 `maxTime` 必须有限正数，否则抛 `RangeError`；校验收到的参数一律不修改。

容差按任务书要求只针对实际游戏量级（米、720 m/s、0..2 秒）设定，未构造通用高精度系统。

## 用例覆盖（16 项，对应任务书验证项）

| 任务书验证项 | 用例 |
| --- | --- |
| 静止目标 | a static target is hit at the direct flight time（500 m → 0.694444 s） |
| 横向目标 | a perpendicular target is led by the exact closed-form amount |
| 迎面目标 | a head-on target is intercepted before the mid-point |
| 远离且更快无解 | a target fleeing faster than the projectile has no solution |
| 等速退化线性情况 | equal speeds degenerate to the linear case（接近 / 远离 / 侧向三种） |
| 最近正根 | the earlier of the two roots is the one returned／the returned time is the earliest intercept, not merely a valid one |
| 超时 | a solution past maxTime is rejected／the maxTime boundary is inclusive／the default maxTime is 2 seconds／a real root that arrives too late is still reported as no solution |
| 重合 | a coincident shooter and target yield time 0 |
| 非法输入 | illegal inputs raise RangeError before any solving（13 组坏向量、9 组坏 speed、7 组坏 maxTime） |
| 不变性 | inputs are never modified（冻结对象 + 返回值不是入参） |
| 代回检查 | 每个被接受的解都由 `assertSubstitutionHolds` 断言 `point == target + v·t` 且 `|point − shooter| == s·t` |

补充：真实游戏量级的 10 组夹具逐一做代回检查（误差均 < 1 帧飞行距离的千分之一）；一个明确超出预算的夹具同时用独立求根确认没有更早的解。

**无解判定的可验证性**：用例不只断言返回 null，还用独立实现的 `analyticRoots` 复核几何——要么判别式为负（无实根），要么不存在落在 `[0, maxTime]` 内的根。`analyticRoots` 已注明在 `a ≈ 0` 时失效（除以零），该退化情形单独用线性式断言。

## 给 Codex 的替换建议与具体示例

任务书要求给出一个具体截击点示例和误差，供决定是否替换 world.ts 中的近似提前量。

**示例场景**（米，右手系，-Z 为前）：
射手位于原点 `(0, 0, 0)`；目标位于 `(0, 120, -360)`，以 `(200, 0, 0)` 匀速横穿；弹速 `720 m/s`。

| 项目 | 数值 |
| --- | --- |
| 精确解时间 | `0.5486377169695913 s` |
| 精确截击点 | `(109.72754339391825, 120, -360)` |
| 代回目标位置 `target + v·t` | `(109.72754339391825, 120, -360)`（差 0） |
| `\|point − shooter\|` 与 `s·t` | 均为 `395.0191562181057`（绝对误差 0，相对误差 0） |
| 直接瞄准当前位置的脱靶量 | `109.73 m` |

即：该场景下精确解与“瞄准敌机当前位置”相差约 110 米，而精确解的两项代回误差都为 0。

**当前 world.ts 的近似做法**（`aimPoint`，供对比，DSH 未改动）：

```ts
const flightTime = target.position.distanceTo(this.player.position) / 720;
return target.position.clone().addScaledVector(this.forward(target), target.speed * Math.min(flightTime, 1.2));
```

差异在于：近似式用**目标自身朝向**（`forward(target)`）作为位移方向，并用目标当前速率乘飞行时间，而飞行时间本身也是按当前位置估的；精确解用真实速度向量 `targetVelocity` 解出最早碰撞时刻。当目标不是正对自身航向平移（例如侧滑、或正在转向）时，两者的提前量方向会不同。

> **更正（2026-10-15，见 Codex 审查 docs/reports/codex-20261015-D07-D08-review.md 第 4 条）**：本节原写「当目标高速接近时，近似式还会低估飞行时间」，方向说反了。`Math.min(flightTime, 1.2)` 是把飞行时间**上限截断**在 1.2 秒，因此在飞行时间本应超过 1.2 秒的远距离/迎面场景中，它给出的是**偏小**的提前量位移，而不是低估时间——就「时间」而言，直接距离/弹速相对真实截击时间是**高估**（真实截击点更近、更早）。D07 报告属历史证据，保留原文并在此更正，后续以当前求解假设与代码为准。

**替换建议**：`solveIntercept(playerPos, targetPos, targetVelocity, 720, 2)` 可直接替换 `aimPoint` 的返回值，接口是纯函数、不依赖 Three.js（调用方传 `{x,y,z}`）。需要 Codex 决定的是 `targetVelocity` 的取法：world.ts 每步都保存了 `previous`，可用 `(position − previous) / dt` 得到当步真实速度；或直接用 `forward(target) × speed` 保持现有语义但获得精确求根。若替换，建议同时保留 `Math.min(flightTime, 1.2)` 那类保护以外的 null 处理（无解时回退为直接瞄准目标当前位置）。**DSH 未自行替换，等待 Codex 决定。**

> **集成结果（2026-10-15，Codex 已接入，本节建议已落地）**：Codex 判定 D07 为 DONE 并接入 `world.ts`——新增 `muzzlePosition` 与 `interceptPoint`，`aimPoint` 改为 `interceptPoint(target) ?? target.position.clone()`，即**无解时回退为目标当前位置**；`targetVelocity` 取 `forward(target) × speed`（与现有 AI 逐步平移模型一致，未引入上一帧位移差分）；弹体改为从实际炮口出发，速度 720、寿命 2 秒由同一组常量同时供求解与生成使用；HUD 在无解时隐藏提前量、连线与瞄准反馈并提示“暂无有效截击点 · 接近目标”。AI 自身原有的射击提前量未改动。Codex 实测整局脚本由 114.3 秒/148 发/母舰 592/玩家 75 变为 136.6 秒/183 发/母舰 532/玩家 60，仍为 11 击毁且双方存活——**精确匀速解不等于更容易通关**，也不能用脚本代替真人平衡验收。

## 已知问题

1. 求解假设目标在弹体飞行期间**严格匀速直线**。目标每步转向时，解会有偏差；world.ts 每步重算提前量可缓解，但这不是追踪解。任务书只要求匀速解，未做扩展。
2. `a ≈ 0` 的判定阈值取 `|a| <= Number.EPSILON * max(s², 1)`。目标速率与弹速极接近但不完全相等时，仍走二次式分支；此时判别式接近零，两个根几乎重合，返回的仍是有效根（已由代回检查兜底）。
3. 代回自检的相对容差为 `1e-6`（作用于 `max(1, reach²)`）。这是为了不返回假命中，不用于提升精度；如需更严或更松需明确。
4. 重合判定用距离平方 `<= 1e-18`，即约 1e-9 米。真实单位（米）下这远小于任何实体尺度，不会误判近距目标。
