## 实现行为

- loadSettings：`getItem` 抛错、返回 null/undefined、JSON 解析失败、非对象（含数组、字符串、数字、布尔、null）、`version !== 1` 均返回一份**新的完整默认设置**（不是部分合并，也不是 DEFAULT_SETTINGS 本身）。
- 合法 version=1 对象按字段恢复：volume 有效有限数值时夹在 [0,1]；sensitivity 有效有限数值时夹在 [0.2,3]；quality 仅接受精确的 `low`/`medium`，否则取字段默认值；缺失字段取该字段默认值；忽略额外字段。布尔、字符串、null、数组、对象形式都不强转。
- saveSettings：按同一套 normalize 规则处理后写入（运行时不信任 TS 类型），JSON 只包含 version/volume/sensitivity/quality 四个字段；写入使用 SETTINGS_KEY；setItem 成功返回 true，抛异常返回 false；不产生弹窗、不记录私密数据（额外字段与未知字段均不写入）。
- 公共 API 仅两个函数；normalize 为模块内部实现，未导出。

## 用例覆盖（16 项，对应队列必测项）

| 队列必测 | 用例 |
| --- | --- |
| 空值/坏JSON/null/数组/旧版本 | malformed, empty and non-object payloads fall back to defaults（21 种载荷） |
| 缺字段 | missing fields take the field default while valid siblings survive |
| 越界数值 | out-of-range numbers are clamped to the documented bounds |
| 字符串数值 | string, boolean and null numbers are not coerced |
| 错误quality | only low and medium are accepted qualities（含大小写、空串、数字、数组） |
| getItem/setItem抛错 | a storage read error degrades to defaults…／a storage write error is reported as false, never thrown |
| 完整保存加载往返 | a save then load round trip preserves every field |
| 不污染默认值 | DEFAULT_SETTINGS and the caller value are never modified |
| 忽略额外字段 | loading ignores extra fields |
| 检查写入的准确key与字段 | saves write only the four agreed fields and the exact key（断言 key 等于 `starfighter-guard:settings:v1`，载荷键集合恰为四项，且不含私密字段） |

补充：初始空存储的完整默认值、version=1 边界值恢复、保存前对敌意值归一、重复保存覆盖而不累积、以及通过 Proxy 断言模块只读取约定字段（the module reads only the four documented fields）。

## 已知问题

1. `loadSettings` 对 `version` 使用严格相等 `=== 1`：`"1"`、`1.0` 之外的任何形式（字符串、null、布尔）都回退默认。这符合契约「version不等于1返回默认」，但如果有旧版本迁移需求，需要 Codex 在契约中明确迁移策略。
2. 存储键固定为 `starfighter-guard:settings:v1`（来自 shared/config），版本升级时需要新键或迁移逻辑，当前未实现也未被要求。
3. `StorageLike` 只声明 getItem/setItem；真实 localStorage 的 removeItem/clear 未被使用，避免越权删除用户数据。
