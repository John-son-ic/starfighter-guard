## 实现契约对照

| 任务书要求 | 实现 |
| --- | --- |
| 仅用 Node 内置模块 | 只 import `node:fs`、`node:path`、`node:url` |
| 导出 `packRelease({ projectRoot, outputRoot })`，返回新生成目录绝对路径 | 是；返回 `{ outputPath, fileCount, totalBytes, files }`，`outputPath` 为绝对路径 |
| 被 import 无写入副作用 | 是；入口判定用 `import.meta.main`，写操作只在 `packRelease()` 内 |
| CLI 默认 projectRoot 为项目根、outputRoot 为 `artifacts/local/release` | 是；两者都由脚本位置解析，不依赖 cwd |
| 打包前要求 `dist/index.html`、D09 脚本、启动器、本项说明存在；缺项非 0 退出并给出准备步骤 | 是；任一项缺失即抛错，CLI 退出码 1，且**不创建输出目录** |
| 不自动运行 npm 安装/构建 | 是；只读复制，不 fork 任何子进程 |
| 每次创建不冲突的新子目录，不删除/覆盖旧包 | 是；用 `mkdtempSync(output, 'pack-')` 生成唯一目录，旧包原样保留（测试用 marker 文件证明） |
| 不递归移动源目录 | 是；只按明确清单复制 |
| 输出路径不能位于 dist 内 | 是；`isInside(dist, output)` 检查 |
| 明确清单：`dist/**`、`scripts/serve-release.mjs`、`start-play.cmd`、说明（复制为包内 README.md） | 是；清单之外一律不复制 |
| 禁止复制仓库根、.git、node_modules、源码、代理/环境文件、历史截图、测试夹具 | 是；夹具里放了 7 类诱饵文件，测试断言它们全部不出现 |
| 拒绝复制符号链接 | 是；`lstatSync().isSymbolicLink()` 检出即报错并终止 |
| 包内结构保持 `dist/`、`scripts/serve-release.mjs`、`start-play.cmd` | 是；相对路径不变，D09 的 `../dist` 仍成立 |

| 输出生成路径、总文件数、总字节数即可 | 是；三分项，无 ZIP、无压缩框架、无版本管理 |

### 实现过程中发现并修掉的一个自身设计错误

**误把“输出目录位于项目内”当作禁止条件。** 初版写了 `isInside(output, source)` 就报错，但任务书指定的默认输出 `artifacts/local/release` **本身就在项目根内**，这条检查会让默认用法直接失败。任务书真正禁止的是「输出路径位于 dist 内」和「复制源自身」，因此改为只拒绝：输出等于项目根、输出位于 dist 内。测试同步改为「项目内输出允许、dist 内与项目根自身拒绝」。

该缺陷由 Codex 在并行审查中先行指出（见 docs/reports/codex-20261015-D07-D08-review.md 第 30 条，其中记录了 `package-release.test.mjs` 该用例失败），DSH 随后修正并通过。

## 已知问题

1. **包目录名是 `pack-<随机6位>`**（`mkdtempSync` 的命名）。可移动、不冲突，但不含版本号或日期；任务书要求“不冲突的新子目录”且不做版本管理，故未扩展。
2. **包是构建快照**：开发副本重新 `npm run build` 后必须重新打包（说明文件已写明）。
3. `dist/models/README.md` 会一并进入包（它属于 `dist/**`）。这是构建产物自身的内容，符合“只复制 dist/**”的清单，未做额外过滤。
4. 打包器不校验 `dist` 内容是否与该次构建一致（不比对 manifest 字节数）——那属于 D06 的 `assets:verify` 职责，已独立存在于门槛中。
5. 未生成 ZIP 或安装程序（任务书明确不做）。
