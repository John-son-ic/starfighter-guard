# Codex / DSH协作

能力分工采用用户对本地工具的观察，不根据公开榜单宣称固定强弱。DSH是harness，实际表现也依赖其模型、配置和工具。这里无需比较订阅、模型排名或改动Agent配置。

## 主责

| 工作 | Codex | DSH |
| --- | --- | --- |
| 需求收敛、架构、接口、依赖选择 | 主责 | 提出明确问题 |
| 模型、配色、HUD、摄像机、图像判断 | 主责并验收 | 不自行修改 |
| 飞行手感、AI绕舰、空间碰撞、集成 | 主责 | 提供日志及可复现输入 |
| 状态机、数值工具、存储适配 | 设计契约、审查 | 实现 |
| 边界用例、确定性回归、故障复现 | 审查难点 | 主责 |
| 最终完成判断 | 运行、视觉与游戏验收 | 如实报告机器检查 |

## 推荐：同目录轮流交接

用户将此目录交给DSH。Codex本轮结束后DSH开始写入；DSH完成一个工作包就更新报告。用户切回Codex时让DSH保存并停止写入。无需用户逐行复制代码。

DSH直接保留文件改动，默认不创建分支、不提交Git；Codex审查后按任务提交。这减少普通用户处理分支的负担。任何一方开始工作都先检查git status；发现另一方正在写，等待交接或改做只读检查，不覆盖文件。

若将整个文件夹复制到别处，属于独立副本：保留.git与基线commit，DSH在副本建立自己的分支、按任务提交，由Codex导入commit/bundle。不能把两份文件夹直接全量覆盖。node_modules和dist无需复制，npm ci可重建。

将来确需同时开发时，由Codex建立独立Git worktree，再指定文件所有权和集成点；初版不让用户承担该流程。

## 任务状态

READY → DOING → REVIEW → DONE；遇阻塞可记BLOCKED并选择其他READY项。REVIEW表示实现和自测完成，DONE需Codex验证。依赖可区分“接口已固定”和“实现待审查”，不能把尚未通过测试的实现当作稳定依赖。

每项只做约定文件。需要修改共享接口或图形文件时，在报告中说明最小变更建议与原因，等待Codex处理；其他独立任务继续。已有明确授权的工作不反复向用户索要确认。

## 抗中断

- 每个工作包完成立即更新摘要与独立报告，不等整轮结束。
- 中断前记录正在修改的文件、剩余步骤、检查命令及结果。突然中断恢复时以磁盘与git diff为准。
- DSH更新DSH_REPORT.md和自己的队列状态；Codex更新CODEX_RESUME.md与任务验收状态，避免争写同一份进度文件。
- 报告不填估计的测试结果；失败保留退出码和摘要；没运行就写“未运行”。
- 同一错误两轮针对性修复仍未解决，记录最小复现后转向其他任务。
- 队列完成后停止新增工作，写清可继续的候选项；“可持续运行”不等于无限轮询、无休止测试或擅自扩展范围。

本仓库没有安装自动调度器。聊天结束不代表任何Agent会在后台持续执行；是否保持运行取决于用户启动的DSH会话。文档支持反复恢复，不保证自动重启。
