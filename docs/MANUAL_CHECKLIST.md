# 人工试玩检查表

C07更新：本表当前人数/波数已改为4架僚机、5波46架敌机。额外观察撞舰后是否能继续转向、画面是否正常，以及母舰炮塔能否转向开火。记录列仍须由实际试玩者填写；自动化截图不代填真人结果。

用途：供**人**按步骤实际操作并记录观察结果。本表不预填通过项，也不代替视觉验收。

## 使用方式

- 每项包含：**步骤 → 期望观察 → 记录**。
- “记录”列留空，由实际执行者填写（通过 / 未通过 / 存疑），并写下看到的现象、时间点与截图文件名。
- 只记录能看到、能复现的事实。不要因为“页面能打开”就判定视觉或性能通过。
- 帧率一栏只填本机实测读数，并注明设备与浏览器；不要用软件渲染结果推断硬件性能。
- 建议在开始前先备份当前设置（记下音量/灵敏度/画质），结束时恢复。

前置：`start-dev.cmd` 或 `npm run dev` 能正常打开页面；浏览器支持 WebGL 2。

本地静态启动与打包工具不会改变游戏画面或玩法。若用离线包，前置条件改为“包内 `start-play.cmd` 能打印出地址”；工具的自动验收记录单独保存，不填写成本表的真人试玩结果。

## B. 目标与提前量是否看得见

| B1 | 第一波出现后按 Tab | 画面右下方、底部仪表上方的目标读数出现名称与距离；该敌机标记变为锁定样式（框变大、出现血条） | |
| B2 | 连续按 Tab 数次 | 目标按距离顺序轮换，不会卡死或丢失读数；血条跟着当前锁定目标走 | |
| B3 | 锁定后观察金色提前量圆环与连接敌机的虚线 | 圆环相对敌机的位置**取决于目标的运动方向**：目标横穿时圆环明显偏在其运动前方，目标几乎静止或正对/背对你时圆环接近机身（按匀速截击解计算，不再带 1.2 秒截断）。**不要预设它永远在前面** | |
| B4 | 对着提前量圆环开火（保持机头大致对准） | 命中反馈 × 出现；连续命中才会击毁目标并让击毁计数增加。**单发不保证击毁**——随目标剩余机体而定 | |
| B5 | 故意对着敌机机身（偏离提前量）开火 | 命中率**通常**明显下降，但不是必然全空：离提前量很近时仍可能打中，且开火方向在约 4° 以内会自动修正到截击方向。请记录实际偏差多少才开始明显打不中 | |
| B6 | 等目标开始持续转弯后再观察提前量圆环 | 圆环按目标**当前**航向外推，目标转弯后会偏；请记录偏离幅度以及是否需要边打边修 | |
| B7 | 追一个高速远离的敌机（例如它正朝远处飞） | 无有效截击点时圆环与虚线**隐藏**，右下角提示“暂无有效截击点 · 接近目标”；靠近后圆环重新出现 | |
| B8 | 把视线转到看不到目标的方向 | 目标标记移到画面边缘并变成指向它的橙色三角（三角会随方向旋转）；右下角提示“目标在视野外 · 按箭头转向” | |
| B9 | 观察画面中其他舰船标记 | 可见的敌机与友机都有标记，并显示机型名与距离数字；母舰标记是一个青色小圆环，带“守望号”与距离 | |
| B10 | 观察敌机标记与友机标记 | 敌我颜色可区分（敌机偏暖、友机与母舰偏青），不会混淆 | |
| B11 | 观察提前量是否被母舰舰体挡住（让舰体拦在你与目标之间） | 提前量圆环与虚线**隐藏**，锁定标记变虚线框，右下角提示“舰体遮挡 · 请改变攻击角度” | |
| B12 | 把母舰转到视野之外 | 母舰标记停在画面边缘，变为青色方向三角，仍标注“守望号”与距离 | |
| B13 | 把一架僚机转到视野之外 | 僚机标记**直接消失**，不在边缘留箭头——这是当前行为，请按现状记录，并记下这是否让你难以找回僚机 | |

记录要点：提前量圆环是否与准星混淆、虚线是否看得清、屏外三角方向是否指对、遮挡与“暂无有效截击点”提示是否及时。

## 与自动检查的分工

- 本表是**人工**观察记录，不替代自动测试。
- 逻辑回归：`npm test`；集成门槛：`npm run check`（依次运行类型检查、全部行为测试、模型文件一致性检查 `npm run assets:verify`、构建）。
- 模型文件一致性可单独运行：`npm run assets:verify`。
- 本地静态启动工具可单独检查：`node --test tests/dsh/release-server.test.mjs`；离线打包可单独检查：`node --test tests/dsh/package-release.test.mjs`。这两项是机器检查，只覆盖“能正确地把已构建文件发给浏览器”，**不代表画面、手感或性能验收**。
- 视觉呈现、模型比例与飞行观感的最终判定由 Codex 负责；本表只提供可复现的操作步骤与期望现象。
- 本表由 DSH 依据 `src/app/game/` 的实际实现编写（第四批校正依据 `world.ts`、`start.ts`、`hud.ts`、`audio.ts`、`flight.css`、`hud.css`）；表中未填写任何通过项，所有“记录”都需要真人实际操作后填写。
- **第四批尚未由真人执行**：A11 与 D09/D10 相关条目均为待验收状态，不能把脚本通过当作真人试玩通过。
