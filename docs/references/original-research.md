# 星战太空战：背景与网页端实施方案

调研日期：2026-10-15。当前交付为设定及实施方案，尚未开发游戏。

## 1. 推荐立项方向

做一款单人、三维、第三人称追尾视角的太空空战游戏：玩家作为一名原创绝地将军，驾驶 Eta-2 Actis 绝地截击机，带领克隆人飞行员，在一艘共和国狩猎者级歼星舰周围迎击贸易联盟支持的分离势力机器人航空部队。

首关目标是保护母舰完成抢修与撤离，单局约 8—12 分钟。先制作一个完整可玩的关卡，再考虑多关卡、更多可驾驶机型和大型舰队战。

本稿中的“原创设定”“游戏规则”“建议数值”均是本项目的设计，不代表星战官方设定。来源优先采用 StarWars.com Databank；Eta-2 的护盾细节及三联战机的背景补充采用 Wookieepedia 的正史条目，未采用其 Legends 页面数值。

## 2. 世界观与时间线

### 2.1 推荐年代

设在克隆人战争后期、66号令之前，约 19 BBY。BBY 是以雅文战役为参照的纪年，“19 BBY”即雅文战役前约19年。这里的具体作战行动属于原创支线，不能当作正史中已发生的战役。

选择这个时期是因为 Eta-2 已投入使用，ARC-170、狩猎者级与分离势力机器人机群能够同时出现。官方条目确认阿纳金、欧比旺在科洛桑战役驾驶 Eta-2；Wookieepedia 正史条目补充了其在战争最后一年的广泛使用。[1][2]

如果改成较早期的克隆人战争，应重新评估玩家改用 Delta-7/Delta-7B、友军采用 V-19 的组合。本项目首版固定在后期，避免为年代分支增加工作量。

### 2.2 双方阵营的正确表述

- 共和国一方：银河共和国海军、绝地将军、克隆人飞行员。
- 敌方：独立星系邦联（CIS，亦称分离势力）的航空部队，带有贸易联盟背景。

贸易联盟与分离势力有关联，但两者并非同一个组织。官方条目说明贸易联盟在克隆人战争期间秘密加入杜库的分离组织，参议院代表则试图否认。剧情中可称“贸易联盟支持的分离势力部队”，保留用户原始构想，也避免把所有分离势力装备都称作贸易联盟自有装备。[3]

机器人战机通常就是具有机器人智能的飞行器，不必安排一台 B1 坐在驾驶舱里。秃鹫战机的后期型号具有一定自主性，因此不采用“摧毁一艘控制舰，所有敌机立即关机”的通关方式。[4]

### 2.3 狩猎者级在关卡中的作用

狩猎者级采用共和国时期的灰白船体、红色标识和双舰桥轮廓。官方“共和国攻击巡洋舰”条目给出 1,155 米舰长，并描述了重武装、背部大型飞行甲板及侧下方较小的出入口。[5]

关卡把它同时作为：

1. 尺度参照物：掠过舰桥、炮塔与引擎时，玩家能感到自己只是小型战机。
2. 战术地形：舰体遮挡视线与射界，舰首、舰腹、舰尾形成不同交战区。
3. 保护目标：轰炸机有明确攻击对象，玩家必须选择优先级。
4. 战场支援：近防炮攻击进入射界的敌机，重炮与远处敌舰交火。

母舰应当有实际作战能力。通过原创的护盾受损、局部防空缺口和多方向来袭，解释玩家出击的必要性。

## 3. 首关原创背景：余烬航道

以下舰名、地点、人物和战况均为原创暂名。

克隆人战争后期，一支共和国分遣队护送撤离船只穿越外环一处补给航道。主力舰先行接应运输队，狩猎者级“守望号”留在后方掩护。

一轮突袭损坏了“守望号”的超空间导航设备和右舷局部护盾。维修组预计需要数分钟恢复跳跃能力。贸易联盟支持的分离势力部队发现这个机会，派出机器人航空编队，试图先摧毁引擎，再迫使舰船失去行动能力。

玩家是一名原创绝地将军，已经在舰外巡逻。接到警报后，与克隆人航空队一起迎敌。共和国舰长负责全舰作战，玩家仅指挥分配给自己的战机分队。

开场通讯示例：“将军，右舷护盾还没恢复。敌方轰炸机正在接近引擎——我们需要你们争取时间。”

远处可放置敌方母舰剪影，解释敌机来源。首版将其作为远景与增援来源，不开放其内部，也不要求玩家将其击沉。

## 4. 双方机型与职责

下表的战场职责和数量是游戏设计；机型及阵营依据相应资料。

| 阵营 | 机型 | 关卡职责 | 首版配置 |
| --- | --- | --- | --- |
| 玩家 | Eta-2 Actis 轻型截击机／绝地截击机 | 高机动缠斗、紧急拦截、标记目标 | 1架 |
| 友军 | ARC-170 星际战斗机 | 持续火力、编队支援、保护母舰 | 4架，其中2架接受直接命令 |
| 友军扩展 | V翼战斗机 | 快速截击与外围巡逻 | 后续加入，首版不依赖 |
| 敌军主力 | 秃鹫机器人战机 | 数量压制、掩护轰炸机、牵制玩家 | 分批投入，累计约18—24架 |
| 敌军任务单位 | 鬣狗机器人轰炸机 | 向母舰关键部位发起重武器攻击 | 分两批投入，累计约4—6架 |
| 敌军精锐 | 机器人三联战机 | 追尾、侧击、压迫僚机 | 最后阶段2—3架 |

数量为调试起点，完整场景内可战斗的敌机建议硬上限16架，友军4架，玩家1架。性能较低时先减少装饰编队、粒子和分辨率，再评估调整实战单位数量。

### 4.1 玩家：Eta-2

官方确认 Eta-2 比 Delta-7 更小、火力更强，长度为5.47米；其轮廓与《西斯的复仇》开场直接对应。[1]

推荐武器为主激光炮与后续加入的离子炮。首版不默认给它配置电影中未体现的导弹武器。Wookieepedia 正史条目记载标准 Eta-2 没有护盾，因此界面采用“机体完整度、武器热量、加速能量”，不设置自然回满的标准护盾。[2]

降低新手挫败感的方法是较宽容的敌机命中率、受击预警、难度选项和检查点；如以后加入“原力专注”，应标明它是游戏机制，首版也无需依赖该技能。

### 4.2 友军：ARC-170

官方描述了三名克隆人乘员、前向武器、后向炮塔及负责机上修理的宇航技工机器人。[6]

首版用一个飞行AI控制整架战机，尾炮单独进行有限射界索敌，无需模拟三名乘员。它应比玩家更稳定、更适合提供火力支援，具体速度和耐久是游戏平衡参数。

V翼确实在克隆人战争期间由共和国投入使用，可作为后续快速截击单位；首版用ARC-170足以建立明显的友军身份。[7]

### 4.3 敌军：三种威胁形成选择

- 秃鹫：官方强调数量进攻及机器人可承受的高强度机动。游戏中用三机小队轮流攻击，避免所有单位同时瞄准玩家。[4]
- 鬣狗：官方定位是配备重型弹药的自动轰炸机。首关将其设计为沿攻击航线接近母舰并发射可拦截弹药；这一攻击流程属于游戏化设计。[8]
- 三联：正史资料将其描述为擅长激烈近距缠斗、具有较先进机器人智能的战机。游戏中让它更会追尾、脱离及侧击，而非只增加生命值。[9]

## 5. 首关流程与胜负条件

| 阶段 | 预计时长 | 玩家行动 | 设计目的 |
| --- | --- | --- | --- |
| 舰外集结 | 约1分钟 | 绕过舰桥、确认目标、召回僚机 | 学习操控与母舰方位 |
| 第一轮接敌 | 约2分钟 | 击退首批秃鹫小队 | 建立追击、瞄准与射击反馈 |
| 紧急截击 | 约3分钟 | 放弃部分缠斗，转向攻击右舷的轰炸机 | 引入目标优先级与僚机命令 |
| 最终掩护 | 约2—3分钟 | 应对三联战机与最后一批轰炸机 | 同时运用飞行、射击、指挥 |
| 撤离窗口 | 约1分钟 | 飞入安全集结区，触发编队回收／撤离演出 | 形成完整任务收束 |

阶段由任务事件与最小时间间隔共同触发。玩家表现好可以提前推进，表现差也不会无限堆叠敌机。所有增援从可解释的入口生成，避开玩家近距离视野并提前播报。

胜利：维修完成、母舰保持存活，并在最终窗口解除迫近的轰炸威胁，玩家抵达集结区。随后以短演出完成回收与跳跃，不要求首版制作手动机库降落。

失败：玩家机体被摧毁，或母舰核心耐久归零。关键子系统受损首先造成局部失效与任务压力，首版只保留母舰核心一个保护失败条件。战斗开始后设置阶段检查点。

可选目标：保住两架直属僚机、减少母舰损伤、在投弹前击落轰炸机。无需击落所有敌人即可完成主任务。

## 6. 飞行、射击与指挥

### 6.1 操控与视角

采用街机化三维自由飞行：俯仰、偏航、滚转均可，速度有上下限，默认飞行辅助减少侧滑。首版以第三人称追尾视角为唯一主要视角。

建议操作：鼠标指向控制转向，W/S 调节推力，A/D 横向推进，Q/E 滚转，Shift 加速，左键激光炮，Tab 切换目标，1/2/3 下达指令，Esc 暂停。按键最终以可玩测试为准。

不模拟大气升力、失速或重力下坠。用惯性、加速度上限、有限转向速率与短时加速保留飞行重量感。接近母舰时提供明确碰撞预警，越界时给出返航提示。

鼠标控制先采用画面中心死区与偏移转向，不依赖锁定指针；若加入 Pointer Lock，必须由用户点击开始，并正确处理退出锁定与暂停。[10]

### 6.2 战斗反馈

- 激光为有飞行时间的弹体，提供目标提前量提示与有限瞄准辅助。
- 连续开火产生热量，玩家需要在追击中管理射击窗口。
- 展示命中反馈、敌机失控、爆炸、任务击杀确认，避免只有血条变化。
- 给离屏威胁添加方向箭头；轰炸机用独立图标、距离与攻击倒计时提示。
- HUD显示机体、热量、加速能量、当前目标、两架直属僚机状态和母舰核心状态。
- 敌我识别同时使用颜色、形状与文字，不只依赖激光颜色。

### 6.3 三条僚机命令

1. 跟随掩护：两架僚机在玩家附近保持松散队形，攻击逼近玩家的敌机。
2. 集火目标：攻击玩家标记的合法敌方目标，击毁后回到掩护状态。
3. 保卫母舰：优先截击进入防御区的轰炸机，其次攻击护航机。

命令在HUD和无线电文字中确认。直属僚机应实际改变目标和航线；其余两架友军由任务AI管理，避免让玩家承担整支舰队的微操。

## 7. 网页端技术方案

### 7.1 技术选型

推荐 TypeScript + Three.js + Vite，战斗场景用WebGL渲染，HUD用HTML/CSS，音效用Web Audio。Three.js的WebGLRenderer目前要求WebGL 2，因此首版面向启用硬件加速且支持WebGL 2的桌面浏览器，加载前检测支持情况。[11]

不需要战斗服务器、账号或数据库。关卡和机型参数存为JSON，设置与成绩存在localStorage。Vite构建生成静态资源，可通过本地HTTP服务或静态HTTPS托管运行；部署环境按Vite文档配置路径。[12]

交付方式建议为“网页链接 + 完整源码 + 本地启动脚本”。本地资源打包，不依赖在线CDN。由于ES模块和模型加载可能受file协议限制，桌面双击入口应启动本地服务后打开浏览器，不承诺直接双击index.html就能运行完整版本。

后续如需安装与断网运行，再增加PWA缓存和资源版本管理。首版不加入联网多人、移动端触控或VR。

### 7.2 模块划分

| 模块 | 职责 |
| --- | --- |
| GameLoop | 固定步长模拟、插值渲染、暂停与恢复 |
| FlightSystem | 推力、转向、加速、飞行辅助与边界 |
| CombatSystem | 武器冷却、弹体、命中、伤害与击毁 |
| AISystem | 编队、索敌、攻击、脱离、轰炸与避障 |
| SquadronSystem | 接收玩家命令、分配目标、显示执行状态 |
| MissionDirector | 波次、阶段、目标、无线电与胜负 |
| CapitalShipSystem | 母舰耐久、关键部位、炮塔与损伤表现 |
| RenderAudio | 模型、LOD、光效、粒子、摄像机与音效 |
| HUD | 雷达、目标标识、任务状态、设置与结果页 |

机型参数和关卡配置与系统逻辑分离，允许后续加入V翼、另一艘母舰或新任务时复用代码。

### 7.3 飞行AI实现

无需大语言模型控制每架飞机。采用有限状态机及局部转向行为：集结 → 选敌 → 接近 → 攻击窗口 → 脱离 → 重新攻击；受威胁时切入闪避，所有状态优先处理避障。

所有单位共用带机型差异的运动控制器，遵守最大速度、转向率及射击条件。每架敌机用略有差异的决策间隔、瞄准误差和攻击节奏。

轰炸机使用接近航点、投弹航线、撤离航线；战斗机根据距离、威胁、任务目标评分选敌，并限制同时追击同一对象的数量。AI决策可降到每秒5—10次，飞行与碰撞持续按固定步长更新。

母舰周围使用多层碰撞体与预设通道：外围提前避让，中近距离检测飞行方向，最后用实际碰撞保证不可穿模。不能只用一个包围整舰的大盒子，否则会出现空旷区域无法飞行的问题。

### 7.4 碰撞与武器

战机先采用球体／胶囊体，母舰采用分段凸体与少量精细碰撞区域。弹体使用上一位置到当前位置的线段检测，取最先命中的对象，避免高速弹丸穿透薄结构。舰体必须阻挡视线和弹体，友军AI同样遵守遮挡。

第一版不用完整刚体物理引擎。先自定义运动、碰撞与受击响应；确有复杂残骸需求时再评估引入。

### 7.5 性能与资源预算

以下均为待实测的工程目标，不是已验证的性能承诺：

- 同屏实战单位约21架以内，远景编队只播放简化路径，不参与完整AI和碰撞。
- 中档桌面设备1080p争取60fps，低画质争取稳定30fps；首次性能里程碑记录具体CPU、GPU、浏览器和测试条件。
- 首屏核心资源争取压缩至30MB以内，其余音效和模型分阶段加载。
- 模型使用GLB/glTF，Three.js的GLTFLoader支持该资源流程。[13]
- 共享材质、合并母舰静态结构、LOD、对象池和实例化用于高频重复对象。
- 激光与引擎以自发光材质为主，不给每发弹丸配置动态点光源。
- 辉光、阴影和粒子数量提供质量档位，限制渲染像素比，避免高DPI屏幕突然加重负载。
- 模拟使用固定步长，限制每帧补算次数；失焦自动暂停，恢复时不积算一大段离线战斗。

## 8. 美术与声音制作

首阶段用程序化低模还原机型轮廓：狩猎者级的楔形、红色中轴和双舰桥；Eta-2的分叉前部与中央座舱；ARC-170的宽翼；秃鹫、鬣狗、三联各自明显不同的剪影。

可玩后再替换精细模型。母舰重点制作玩家会近距离经过的舰桥、侧舷、机库口和尾部引擎，其余区域采用重复结构与贴图细节。避免尚未验证玩法就投入整艘电影级母舰。

声音优先解决空间方向和任务提示：激光、引擎、命中、爆炸、锁定警报及少量无线电文字／语音。不同阵营采用可区分的音色。配乐和配音可后置。

资产清单记录作者、来源、授权及修改信息。星战名称、造型和音乐涉及既有IP；本稿没有核验任何对外发行许可，公开发布与商业化所需授权另行确认。原型使用自制或具有明确使用许可的资源，不从现有游戏提取模型、音频。

合计约13—23人日。实际最大的变量是模型质量、摄像机与操控手感、AI绕舰能力。发现风险时优先保持可玩关卡闭环，再缩减装饰和扩展内容。

### 9.1 第一阶段必须验证的难点

1. 飞机能否在母舰附近自然转向，玩家是否容易迷失方位或晕眩。
2. 目标提前量是否可理解，正常玩家能否追上并命中敌人。
3. AI能否连续绕舰飞行，避免频繁撞舰、穿模或在障碍物前抖动。
4. 镜头在滚转、加速、近距离掠舰时是否稳定，是否穿入舰体。

### 9.2 完整版本的验收清单

- 每个阶段都能触发、推进、失败、重试；跳过非必要击杀不会卡关。
- 验证“跟随”“集火”“保卫母舰”会改变僚机目标和航线，命令对象死亡后会恢复合理行为。
- 轰炸机到达攻击窗口会实际造成伤害；及时拦截能明显减少母舰损伤。
- 舰体会挡住激光与AI视线，高速弹体不会越过近距离目标。
- 截图与实际试玩检查尺度、敌我识别、目标可见性、镜头、爆炸遮挡和特效清晰度。
- 记录高压力阶段的帧时间、单位数量与内存趋势，连续重试至少三次检查资源释放。
- 在桌面Chrome、Edge、Firefox上验证加载、开始、音频、暂停和全关流程；其他浏览器作为后续支持范围。
- 处理窗口缩放、失焦、音频未解锁、资源加载失败和WebGL 2不可用情况。

### 9.3 首版暂缓的内容

联网多人、可步行机库、复杂座舱、开放世界星图、程序化星系、大型主力舰全面破坏、数百架完整AI战机、长篇剧情、多种可驾驶飞机和移动端操控。

这些功能不会影响“绝地带领克隆人战机保卫狩猎者级”的首关成立，应在核心飞行与任务完成后独立评估。

## 10. 建议冻结的首版规格

克隆人战争后期；原创绝地将军；Eta-2；一艘狩猎者级；四架友军ARC-170、其中两架可指挥；秃鹫、鬣狗与少量三联战机；第三人称；鼠标键盘；一局8—12分钟；三条编队指令；护舰撤离任务；桌面浏览器；TypeScript + Three.js + Vite；静态部署。

下一步开发首先交付可玩的飞行战斗原型：让玩家在有实体碰撞的母舰旁击落敌机，再推进完整关卡与美术。
